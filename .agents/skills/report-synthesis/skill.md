# Synthesize Findings Into a Report

Use this skill when multiple inputs need to become one coherent report: research findings, logs, sub-agent deliverables, code review notes, source excerpts, or user-provided material. The goal is synthesis, not concatenation.

## Workflow

1. **Read every input fully before drafting.** Partial reading creates reports that repeat early sources and miss later contradictions.
2. **Cross-reference the inputs.** Identify agreement, disagreement, overlap, gaps, and source quality. Surface contradictions explicitly rather than averaging them away.
3. **Decide the organizing principle.** Use the reader's decision, chronology, severity, system area, or evidence strength as the structure. Do not default to one section per source unless that is the clearest shape.
4. **Synthesize, do not concatenate.** Add analysis and connections across inputs. Remove repetition unless repeated evidence materially increases confidence.
5. **Attribute non-obvious claims.** The report should stand on its own, but the reader should be able to trace important claims back to their source.

## Output Shape

Lead with the bottom line. Use headings, bullets, or tables only when they make comparison easier. Keep recommendations separate from evidence when the difference matters.
