# Runtime Refactor and Hardening

This plan consolidates what a full read of the landed PR #5 diff surfaced: the big architectural and correctness debts left by the four bodies of work that landed together (external A2A agents, typed-turn-core, self-managing-turn, retire-history-seq). Each of those has a strong story that holds at the easy boundary and thins out at the hard one — "typed" is typed on the schema→TypeScript edge but the Python emit side builds unchecked dicts; "self-managing" replaced a hard cap with a heuristic that implements one of its four intended signals and false-positives on polling; the god-*methods* were decomposed but the god-*class* grew to 136 methods on one object; retiring `seq` fixed a real race but reintroduced an O(N²) count and left a latent duplication invariant; and the outbound SSRF hardening has no counterpart on the inbound path. This plan makes those claims true. It is a refactor-and-hardening pass with **no backward compatibility** — internal wire shapes, tool signatures, store schema, and class boundaries are all free to change, because nothing outside this repo depends on them and the ideal end state is worth more than any transitional shim. It builds directly on [`typed-turn-core.md`](./typed-turn-core.md), [`self-managing-turn.md`](./self-managing-turn.md), [`retire-history-seq.md`](./retire-history-seq.md), and [`external-agents.md`](./external-agents.md), and where it contradicts a decision recorded in those (most visibly the progress detector), this plan supersedes it.

## Where we are today

**The event contract is enforced on only one of its two edges.** An event is a three-node chain: the emitter (Python), the contract (the Pydantic models in `core/events.py`, from which the JSON schema and the TypeScript `WireEvent` union are generated), and the consumer (the TypeScript reducers). The contract→consumer edge is genuinely enforced — the reducers switch on the generated discriminant and end in a `never` check, so a new backend kind is a compile error. But the emitter→contract edge is on faith: every wire part is built by `_data_part(kind, **fields)` (`a2a_executor.py:421`), a bare `{PART_KIND: kind, **fields}` dict that is never validated against the model it claims to be. `WIRE_EVENT_MODELS` is consumed *only* by the codegen script, never at runtime, despite `events.py:259` describing a "runtime validation dispatch" that does not exist. So a field-name typo in `_data_part("tool_call", toolName=…)` is caught by neither Python, nor tsc, nor the codegen — it silently renders blank in the UI. This is not hypothetical: the codegen's `_strip_titles` (`generate_event_schema.py:35`) deletes *every* dict key named `title`, including the real `title` field on `GroupStartedEvent` and `WarningEvent`, so those fields vanished from the generated types and the reducer now reads them as untyped raw record access (`String(data.title ?? "")`). Underneath, the durability-critical payloads are the *least* typed: `Suspended.interactions: list[Any]` / `plans: dict[str, Any]` (`turn_events.py:146`), `Relayed.event: Any` carrying the entire agents-panel vocabulary verbatim, and `ToolGate` an `extra="allow"` model with a stringly `kind` discriminator. And there is a *second*, entirely separate event vocabulary: the local `make_delegate` (`a2a_executor.py:2623`) and remote `_remote_delegate` (`:2536`) paths both hand-build `{"type": "event"/"started"/"done"/"usage", …}` dicts and each independently re-synthesizes text-block ids. The typed union stops at the runtime↔executor boundary and a duplicated stringly-typed protocol lives at the delegate↔runtime boundary.

**The god-methods shrank; the god-class grew.** `execute()` is now a genuine six-line wrapper and the event sinks are closed unions that raise on an unhandled variant — real improvements. But `AgentRuntime` is a single class of **136 methods across ~3,550 lines**, and `agent.py` is 4,450 lines total. The `_TurnRunner` refactor turned the old 626-line method's argument-threading into ~13 phase methods that communicate through mutable instance vars (`self._message`, `self._task`, `self._updater`, `self._turn_input`, `self._context_state`, … each first-assigned inside a phase body) with an implicit, unenforced ordering contract — calling `_resolve_task` before `_ingest`, or `_compose_turn_input` before `_prepare_runtime`, is an `AttributeError`, not a type error. The complexity was relocated from long methods into temporal coupling, not removed. Three near-identical "self-send a harness message and drain the stream" drivers exist uncoalesced (`_run_autonomous_turn` at `:1809`, `HarnessAgentExecutor._run_compaction_turn` at `:1548`, `resolve_pending_input.drive` at `:2181`), and `_run_compaction_turn` names two different verbs on two classes (one *performs* compaction, one *triggers* it). The executor reaches through object privates for control flow — `self._registry._handlers.get(...)` at five sites, `runtime.background_jobs.has_pending()/has_completed_undelivered()` at five more — so the abstraction the typed contract was meant to establish is bypassed exactly where scheduling decisions are made.

**Tools are a handler-dict of methods, so per-tool policy is scattered and inconsistent.** `_TOOL_HANDLERS` (`agent.py:911`) maps names to `_tool_*` methods, and each tool's sync/background/lease behavior lives wherever that method happens to implement it. The result is incoherent: `timeout` means opposite things across tools — for bash it is a *non-killing inline-wait window* (`tools.py:216`, "does not kill the command"), for `fetch_url`/`download_file` it is the *killing HTTP deadline* passed straight into the request. Only bash got a per-call `background` override; the slow tools always wait exactly `_SLOW_TOOL_SYNC_DEFAULT_SECONDS = 10.0` (`agent.py:862`) with no lever, and `fetch_url`'s HTTP `timeout` default of 30 against that 10 window means any 10–30s fetch always backgrounds with no way to request it synchronously. Bash acquires a worktree `FileLeaseConflict` guard before backgrounding a mutation and releases it in a done-callback (`agent.py:3461`); `download_file`, now also backgroundable, takes *no* lease, so a tracked-tree write can land off-turn with nothing coordinating it against concurrent edits. And the numbers that drive all of this were moved out of the central `tuning` registry into scattered underscore module constants (`_BASH_SYNC_DEFAULT_SECONDS`, `_WEB_SEARCH_SYNC_DEFAULT_SECONDS`, `_SLOW_TOOL_SYNC_DEFAULT_SECONDS`) — same fixed values, less discoverable home.

**The self-managing turn is simultaneously too tight and too loose.** `_TurnProgress` (`agent.py:875`) is the sole backstop on a turn, but it watches only repeated tool-call *signatures* — one of the four progress signals its own spec named (`self-managing-turn.md:30` also lists "a changed tool result for a repeated call, new assistant text or thinking, or an observable state change"). Because `note()` is only ever called with `tool_calls`, never results or text, a legitimate poll-until-ready loop (`bash("curl -s …/health")` returning 503→503→200) has a constant signature and is killed at the fourth identical call *even though the result was changing* — too tight. And because any new distinct signature resets the streak, a wedged model that merely varies its arguments (`echo 1`, `echo 2`, …) loops forever with no iteration, wall-clock, or spend bound — too loose. The `_seen` set grows unbounded for the life of a turn. The vestige of the old cap remains as `_calls_this_turn`, a counter incremented at eleven sites but read once as a single `== 0` boolean ("is this the first iteration") — an error-prone fossil where one missed increment silently re-injects per-turn context. A top-level `stuck` yields `Done(text="", stop_reason="stuck")` with no user-facing explanation (the message only exists on the delegated path). Crucially, the model already has everything it needs to judge its own progress: the previous tool result is in its context, and bash/web_search already write the full output to `/tmp/{id}.log` returned as `output_file` (`tools.py:87,165,255,294`), re-readable even after compaction. The harness is playing detective with less information than the model has.

**Persistence traded a racy O(1) for a correct O(N²), and left a latent duplication invariant.** Retiring `seq` for `row_id` and removing the `_persisted_count` cache genuinely closed the duplicate-key race (the write lock now covers the count-and-insert), and `sqlite_autoincrement` is load-bearing for the newest-first pagination cursor — both good. But `_history_count` is now `SELECT COUNT(*) WHERE task_id = ?` on *every* non-terminal `save()`, once per streamed event, so per-event cost grows with turn length: O(N²) over a turn, on exactly the long event-dense relay turns this store exists to serve, contradicting the module's own O(delta) charter (`task_store.py:20`). Separately, after a terminal compaction the persisted row count is the *compacted* count while `task.history` in memory is still the full uncompacted list; nothing enforces that no non-terminal `save()` ever follows, and if one does, the suffix slice `history[persisted:]` re-appends already-merged messages — silent duplication, safe today only by an unstated assumption. Compaction's insert branch also mints *new* high `row_id`s for overflow messages, which is fine within a task but reorders that task's tail relative to a concurrently-persisted task when `task_page_for_context` interleaves a context by global `row_id`. And durable goal/task state is written clear-then-write (`take_dirty_session_snapshot` clears `_session_dirty` before the write at `agent.py:1606`) across two non-atomic transactions from the checkpoint it rides with, so a crash between them, or a failed write, loses the mutation or leaves conversation and objective at different versions.

**Outbound SSRF is hardened; the inbound path is wide open, and auth is off by default on a tool-executing endpoint.** The outbound A2A client is careful — host-trust at every card/interface/extended-card choke point, redirects disabled, per-agent clients, OAuth refresh with skew and lock. But inbound `FileWithUri` parts are fetched with *only* a scheme check and no host-trust or private-range guard (`a2a_files.py:86`), and every inbound `FilePart` runs through it, so a peer who reaches the endpoint can make the server fetch `http://169.254.169.254/…` or an internal host and have the content re-surfaced to the model. The size cap is applied *after* the whole body is buffered (`a2a_files.py:92`), so a multi-GB body exhausts memory before the 50 MB "ceiling" does anything. Push-notification webhook URLs registered by a client (`app.py:2244`, persisted durably) are POSTed task data with no SSRF check at all. Inbound auth is off by default and the only thing between "unauthenticated" and "arbitrary tool execution" is the `127.0.0.1` bind — an orthogonal parameter that is exactly what you change to use the feature. The per-profile allow-list is bypassed by an empty profile (`remote_agents.py:308`: `not allowed or not profile or profile in allowed` returns True for a sub-agent's empty profile against any agent). The outbound trust check is hostname-string-deep, not resolved-IP-deep, so a DNS name that resolves to a private IP (or rebinds) passes. The OAuth token fetch uses a throwaway client with default `follow_redirects=True` (`remote_agents.py:135`), inconsistent with the discipline everywhere else. An extended-card trust failure is swallowed by a bare `except Exception: pass` (`remote_agents.py:270`). Signed file tokens carry no `jti`/audience (replayable within the window) and `build_file_part` will sign *any* absolute path handed to it, including an in-place `/attachments/reference` path like `/etc/passwd`. CORS is `allow_origins=["*"]` on every route including `/a2a/*`.

## The design

### One event vocabulary, enforced end to end

Collapse the three vocabularies — the typed `TurnEvent` union (runtime↔executor), the `DataPart`/`WireEvent` catalog (executor→web), and the stringly `{"type": …}` delegate protocol — onto **one** generated contract, and enforce it at the emit site. The Pydantic models in `events.py` become the single source of truth *and* the runtime constructor: replace `_data_part(kind, **fields)` with per-event typed emit (`ToolCallEvent(tool_name=…).model_dump()`), so a wrong or renamed field is a `ValidationError` at the source rather than an invisible wire drift. The Python consumers dispatch with `match` + `assert_never` (from `typing_extensions`) so the exhaustiveness the TypeScript side already has holds symmetrically in the backend. The delegate↔runtime boundary stops hand-building dicts and emits the same typed events, and the local/remote text-block-id synthesis is written once. `Suspended`, `Relayed`, and `ToolGate` are given real field types (the interaction, plan, and relayed-event shapes are modeled, not `Any`), which is what makes the suspend/resume durability actually type-checked rather than dict-shaped at its most load-bearing point. The codegen's `_strip_titles` is fixed to strip only Pydantic's injected schema-`title` metadata, never a modeled field named `title`. Because there is no CI in this repo, the regenerate-and-verify guard rides on the build: `bun run build:events` gains a `--check` mode that regenerates into a temp path and fails on any diff, and `next build` invokes it, so a stale generated file cannot ship. The `check_typed_boundaries.py` regex-linter — already removed as dead — is not resurrected; the generated contract plus emit-site validation *is* the enforcement, structurally, rather than by grep.

### Decompose `AgentRuntime` into composed collaborators

Split the 136-method class along its real seams into collaborators the runtime *composes* rather than *contains*: the model-call loop (streaming, tool-batch, finalize), the tool dispatch/execution layer (below), the permission/gating layer, the session/goal/task state (extending the existing `TaskManager`), the delegation layer (local and remote), and the compaction/observation layer. Each is a focused object with a typed interface; `AgentRuntime` becomes a thin composition root that wires them and owns the turn's identity, not its every behavior. The executor stops reaching through privates: `AgentRegistry` exposes a real lookup instead of `._handlers.get`, and `BackgroundJobs` exposes the scheduling predicates the executor needs (`has_pending`, `has_completed_undelivered`) as its public surface, so those internals can change without breaking the executor. `_TurnRunner`'s temporal coupling is replaced by a **typed phase pipeline**: each phase takes the previous phase's typed output as an argument and returns the next (`Ingested → Resolved → Prepared → Streamed`), so "you cannot stream before the runtime is prepared" is a mypy error, not a runtime `AttributeError`, and the phase ordering is the type signature rather than an unwritten rule. A generic FSM library (`transitions`, `python-statemachine`) is deliberately *not* used — a turn is a linear ~13-phase pipeline, not a cyclic machine, and a hand-threaded typed pipeline is simpler and fully mypy-enforced with zero dependency. The three self-send drivers collapse into one "run a sub-turn and relay its typed events" helper, and the `_run_compaction_turn` name collision is resolved (the trigger and the performer get distinct names).

### Tools as first-class policy-declaring objects

Replace the `_TOOL_HANDLERS` dict and the `_tool_*` methods with a `Tool` protocol: each tool is an object declaring `run`, `permission`, `background_policy`, and `lease_policy`, registered in one place. This is the single change that fixes three inconsistencies at once. `timeout` gets **one** meaning across every tool — "the seconds I am willing to wait synchronously before this backgrounds," the non-killing sense — and a *separate* `hard_deadline` carries "kill after N seconds" for the tools where killing is meaningful, so a model that learns `timeout` on one tool cannot misuse it on another. Every backgroundable tool gains a uniform `background: "auto" | true | false` parameter, visible in its schema with a docstring that explains the tradeoff, so the model *makes* the sync-vs-async decision rather than a hidden constant making it; `"auto"` uses the tool's own `background_policy`. `download_file`'s missing lease is fixed by its `lease_policy` declaring it a tracked-tree write, so the same worktree guard bash uses is applied uniformly by the dispatch layer rather than re-implemented per tool. The genuine physical/security numbers return to **one** central named registry (the `tuning` surface), clearly labeled operator-owned — not scattered underscore constants, and not agency caps.

### Model-owned self-management (interrupt-only)

Delete `_TurnProgress` and the `stuck` stop reason entirely; the harness stops playing detective. In its place, give the model a real primitive and clear guidance. A new `wait_for(seconds)` tool (registered in the new tool registry) performs a cancellable inline wait with no model round-trip, so polling is cheap and intentional — the model does `curl …/health` → reads 503 in its own output → `wait_for(5)` → `curl …/health` → reads 200, instead of hammering an identical call. It is fully interrupt-aware (a turn stop aborts the wait immediately) and holds no locks. The system prompt and the tool descriptions nudge the behaviors we want: end your turn when done, use `wait_for` to poll rather than re-issuing an identical call, re-read `output_file` to check whether a repeated action changed anything, and do not expect a different result from an unchanged call. There is **no** turn-level runaway backstop of any kind: an interactive turn has the human interrupt, and an unattended turn (a delegated sub-agent, an autonomous or scheduled wake) is likewise governed only by the model's own judgment and the human's ability to stop it — this is a deliberate, accepted choice (see tradeoffs). The dead `_calls_this_turn` counter is removed; the one thing it actually encoded — "is this the first iteration," to inject dynamic context once — becomes an explicit boolean set in exactly one place.

### Persistence correctness

Restore O(delta) append without reopening the race. The persisted-message count per task is maintained as an authoritative in-memory counter *guarded by the same write lock that already serializes every writer* — the original bug was never that a cache existed, it was that the cache was not reset when terminal compaction rewrote the rows; the fix is a lock-guarded counter that is set precisely to the compacted length at compaction and incremented by the appended delta otherwise, which is correct by construction because the lock admits one writer at a time. Compaction stops minting new `row_id`s: because compaction only ever *reduces* message count, the compacted prefix is written by **updating the existing rows in place** (overwrite the `message` column of the lowest-`row_id` rows) and deleting the surplus tail, never inserting — which simultaneously eliminates the cross-task global-ordering skew (no new ids appear above a concurrent task's rows) and makes the rewrite a smaller, in-place operation. The latent duplication invariant is closed directly: the store asserts that a terminal save is the last save for a task (a terminal marker on the task's store entry rejects a subsequent non-terminal `save`), so the "persisted rows are a raw prefix of `history`" invariant can no longer be silently violated. Durable goal/task state moves to write-then-clear and rides in the *same* transaction as the conversation checkpoint: `save_session_state` and `save_checkpoint` become one atomic unit, and `_session_dirty` is cleared only after that unit commits, so a failed or crashed write never loses a mutation or leaves objective and conversation at different versions.

### Security hardening (close the inbound/outbound asymmetry)

Give the inbound path the same discipline the outbound path already has. Inbound `FileWithUri` fetches and client-registered push-notification webhook URLs both go through one shared trust guard that (a) resolves the host and checks the *resolved IP* against private/loopback/link-local ranges — not the hostname string — and pins the connection to that resolved address so a rebind between check and connect cannot bypass it, and (b) refuses redirects. The same resolved-IP discipline replaces the hostname-string check on the outbound path, closing the DNS-rebinding gap there too. The ingest size cap is enforced *streaming* — the body is read against a byte limit and aborted when exceeded, never fully buffered first. The empty-profile allow-list bypass is removed: when an agent declares `allowed_profiles`, an empty or unlisted profile is *denied*, not universally allowed, so a delegated sub-agent cannot evade the containment boundary. Auth fails closed on exposure: binding the server to any non-loopback host requires inbound auth to be configured, so the endpoint cannot serve tool execution to an unauthenticated network by omission. The OAuth token fetch uses the same no-redirects client as the rest, so credentials cannot be replayed to a redirected host. The extended-card trust failure surfaces as an `untrusted` health signal instead of being swallowed. Signed file tokens carry a `jti` and audience and are single-use within their window, and `build_file_part` signs only paths under the upload store, so an arbitrary absolute path can never be minted into a URL. CORS is restricted to the app's own origin(s) rather than `*`.

## Build order

Four phases. Phases 1–2 are the interlocking runtime refactor and must land in order (the tool protocol rides on the decomposition, which rides on the one-vocabulary contract); phase 3 (self-management) rides on the tool registry from phase 2; phases 4 (persistence) and 5 (security) are independent of the refactor and of each other and can land in any order relative to it. No backward compatibility is preserved in any phase.

1. **One event vocabulary, enforced.** Unify the three vocabularies onto the Pydantic contract, emit through typed constructors, add `match`/`assert_never` on the Python consumers, model the `Any` payloads, fix `_strip_titles`, and wire `build:events --check` into `next build`. This is first because the decomposition is far safer to perform once every event crossing a seam is typed and validated.
2. **Decompose the runtime and make tools first-class.** Split `AgentRuntime` into composed collaborators, replace `_TurnRunner`'s instance-var coupling with a typed phase pipeline, coalesce the three self-send drivers, remove the private-reach-through, and introduce the `Tool` protocol/registry with uniform `background`, one `timeout` meaning plus `hard_deadline`, and per-tool `lease_policy` (fixing `download_file`). Relocate the physical/security constants back into the central registry.
3. **Model-owned self-management.** Add the `wait_for` tool and the prompt/description nudges, delete `_TurnProgress`, the `stuck` stop reason, and the `_calls_this_turn` fossil. Interrupt-only, no backstop.
4. **Persistence correctness.** Lock-guarded O(delta) count, in-place compaction with no new `row_id`s, the terminal-is-last assertion, and atomic write-then-clear session state.
5. **Security hardening.** The shared resolved-IP trust guard on inbound file fetches, push webhooks, and outbound; streaming size cap; allow-list empty-profile denial; auth-fails-closed-on-exposure; OAuth no-redirects; extended-card trust surfacing; single-use scoped file tokens; CORS restriction.

## Testing

Driven through the fake-LLM turn harness plus targeted live runs, with the bar being observed behavior, not "provably identical" — this changes internal shapes by design. For the vocabulary: an emit-site field typo is a `ValidationError` in a unit exercise; the generated TypeScript is byte-identical after `build:events --check`; a modeled `title` field survives codegen; a delegated sub-turn's events reach the web client through the same typed path as a local turn. For the decomposition: the phase pipeline rejects an out-of-order composition at type-check time; a happy-path turn, a multi-tool batch, a model error, a suspend/resume, a delegated park, and a reconciliation all behave as before against the harness. For tools: `timeout` has one observable meaning across bash and `fetch_url`; `background: true/false/"auto"` each do the expected thing; a backgrounded `download_file` takes the tracked-tree lease. For self-management: a turn that legitimately needs hundreds of rounds completes; a polling loop that previously tripped the detector now runs to completion and `wait_for` is used between checks; an interrupt aborts a `wait_for` promptly. For persistence: a long event-dense turn shows flat per-event append cost (no O(N²) growth); compaction mints no new `row_id`s and cross-task pagination order is stable; a terminal-then-non-terminal save is rejected rather than duplicating; a failed session-state write leaves the dirty flag set and loses nothing; a crash between checkpoint and session state cannot desync them (one transaction). For security: an inbound `FileWithUri` naming a private IP (directly or via a rebinding DNS name) is refused; an over-cap body is aborted mid-stream without buffering; a push webhook to a private host is refused; a sub-agent with an empty profile is denied an allow-listed remote agent; the server refuses to bind a public host without auth; a file token is single-use and cannot name a path outside the upload store.

## Decided tradeoffs

**Interrupt-only everywhere, no runaway backstop — accepted.** With `_TurnProgress` deleted and no spend or wall-clock ceiling, the only thing that ends an unproductive turn is the human interrupt (and, for a genuinely-stuck-but-honest model, its own judgment to stop). An unattended turn that wedges into a subtly-varied loop burns spend until someone stops it. This is a deliberate choice for a self-managing harness that trusts the model and the operator over a heuristic that was, in practice, both too tight (killed legitimate polling) and too loose (defeated by varied arguments); the weight moves to the prompt guidance and the `wait_for` primitive making good behavior easy. Reversible: a soft, unattended-only spend rail is the principled future safety net if this ever bites, and nothing here forecloses it. **No backward compatibility, by direction.** Internal wire shapes, tool signatures, the store schema, and class boundaries all change; there are no shims, no dual-read paths, and no deprecation windows, because nothing outside this repo depends on them and the transitional weight is pure cost. **The god-class is split all the way, not organized in place** — more files and more indirection, accepted as the cost of each collaborator being independently reasoned about, per the "radically good architecture" bar. **In-place compaction assumes compaction only ever reduces count** — true by construction (it condenses), and asserted, so the update-not-insert rewrite is safe.
