# A Typed Turn Core

This is a maintainability plan, not a feature. The A2A-compliance work landed a capable harness, but it grew its turn engine as two enormous methods over untyped dictionaries, and each new capability was threaded through them by hand. The result is high-entropy: `AgentRuntime.stream` and `HarnessAgentExecutor.execute` are hundreds of lines of tangled control flow; a turn's durable state is scattered across stringly-typed `task.metadata` keys; the runtime↔executor contract is an enum tag plus an untyped `**data` bag; the effective permission policy is smeared across a mode string and a redundant boolean trio; a second, untyped event vocabulary rides the wire beside the one typed catalog the repo already generates; "single source of truth" is aspirational rather than real; and the frontend reads the same events as `Record<string, unknown>` and hardcodes user-facing strings in hand-written dictionaries. This plan proposes a *small* set of typed primitives, makes them the load-bearing core, and adapts everything else to fit them — so the next change is a small edit to a typed structure, not surgery on a method too big to test. It builds on [`unified-durable-turn.md`](./unified-durable-turn.md) (which consolidated the persistence but left the god-methods intact) and the findings in [`audit.md`](../audit.md).

## Where we are today

The entropy is concrete and nameable.

**Two god-methods.** `stream()` and `execute()` each interleave a model call, a preflight pass, tool execution, suspension, compaction, steering, and error handling, with `return`/`yield`/`continue` scattered through a fifteen-branch event dispatch. They are too large to restructure safely: unifying the delegated pause in [`unified-durable-turn.md`](./unified-durable-turn.md) had to stop short of the clean version precisely because the executor loop could not be wrapped without re-indenting a method with returns woven through it. A method that is too dangerous to refactor is already too big.

**Blob-soup state.** A turn's durable control-state lives in `task.metadata` under bare string keys — `PENDING_INTERACTION_KEY`, `TURN_KIND_KEY`, `referenceTaskIds`, `agentLane` — read with `metadata.get(...)` and written by dict-spread. The agent's own configuration sidecar (`configuration.json`, including the bash allow-list that `_persist_agent_allow_patterns` rewrites) is likewise read and merged as a raw dict. There is no schema; a typo is a silent bug; the shape is discoverable only by grepping.

**Stringly-typed permissions.** The effective permission policy is encoded twice, and never as a value: as a mode string (`"auto"`/`"read_only"`/`"bypass"`/`"default"`/`"manual"`) compared inline in half a dozen places, and as a redundant boolean trio (`_bypass_permissions`/`_read_only`/`_auto_permissions`) that four separate methods recompute from that string by hand. The delegated "more-restrictive-of-caller-and-card" clamp is open-coded against those booleans. No object answers "what does this turn permit"; the answer is reassembled from scattered flags every time it is needed, and they drift.

**Two event vocabularies, only one typed.** The repo already has an exemplary event catalog: `harness.core.events` (pydantic) generates `events.schema.json`, which generates `events.ts` — one source, zero hand-written type-walking. But a *second* event vocabulary rides the A2A `DataPart.data["kind"]` boundary — `artifact_event`, `compaction_request`, `autonomous_resume`, `input_response`, `artifact_image_annotations` — hand-matched with `.get("kind") == ...` in the executor and read on the frontend as `Record<string, unknown>`. The good catalog and the untyped one describe the same thing and share no code.

**"Single source of truth" that isn't.** The durable-turn work moved the conversation into the task store and *said* the task store is the one surface, but a turn's state is really in four places: the `turn_checkpoint` table, `task.metadata` blobs, the `task_history` wire view, and a wholly separate `background.db`.

**The frontend mirrors the mess.** `reduceDataPart` switches on `String(data.kind ?? "")` and coerces every field with `String(data.x ?? "")`, even though a generated `events.ts` union already exists and goes unused at the read sites. `message.meta` is a `Record<string, unknown>`; `ToolCall` declares `permission`/`question`/`onPermission` props it ignores; and user-facing strings live in hand-written dictionaries (`AGENT_STATE_LABEL_KEY`, tool-status labels, question-option shapes) — hardcoded English, outside i18n.

The unifying disease: **untyped dictionaries and bare strings used as contracts, and control flow too large to see.**

## The core idea

Introduce a handful of typed primitives, make them the only way turn state is represented and moved, and reduce the god-methods to thin drivers over them. They fall into two families — the typed **state** a turn is made of, and the typed **motion** that changes it — plus the frontend mirror and one rule that keeps them honest.

**State — the nouns a turn is made of:**

- **`TurnRecord`** — one typed, serializable value that *is* a turn's durable control-state.
- **`PermissionPolicy`** — the effective permission as a value type, computed once, replacing the mode string and the boolean trio.
- **`AgentConfiguration`** — the agent's sidecar as a validated schema, not a raw JSON dict.

**Motion — how a turn moves and changes:**

- **`TurnEvent`** — a closed, typed union that *is* the runtime↔executor contract, and a member of the one event catalog the wire and frontend already generate from.
- **`TurnMachine`** — an explicit state machine that replaces the tangled control flow; suspension and resume are states, terminals carry a typed `TurnOutcome`, not scattered `return`s and status strings.
- **`TurnStore`** — one facade that owns turn persistence, with an honestly-named `JobStore` beside it rather than a hidden fourth store.

**The frontend event/label model** — the generated union as the *only* reader of parts, and i18n for every user-facing string, killing the ad-hoc dicts.

And the invariant that prevents regression: **no untyped dictionary and no bare stringly-typed enum crosses a module boundary, is persisted, is put on the wire, or is rendered to a user.** A dict is fine as a local, transient computation; it is never a contract, an enum, or a label.

## `TurnRecord`: the one typed control-state

Replace the `task.metadata` string-key soup with a single pydantic `TurnRecord`, serialized under one key and read/written only through typed accessors: the turn `kind` (an enum, from which the restart policy is derived — not a second field), the `pending` interactions as a typed `list[PendingInteraction]`, the resolved `decisions`, the `lane` path, and the `parents`. The `PendingInteraction`, `ToolGate`, and `ToolPlan` values already exist as dataclasses; `TurnRecord` is where they finally live together instead of being flattened into `metadata["pendingInteraction"]["gates"][0]["request_id"]`. Every site that poked `task.metadata` — the suspend handler, the resolver, the reconciliation, the relay — goes through `TurnRecord`, so the reconciliation reads `record.kind`, not `str(metadata.get("daisyTurnKind", ""))`, and a missing field is a validation error at the boundary rather than a `KeyError` three calls deep.

The large, write-cadence-sensitive part — the conversation checkpoint — stays out of the record (in its own table, referenced by task id), exactly as the durable-turn work already separated it; `TurnRecord` carries the reference, not the payload, so it stays small and cheap to rewrite.

## `PermissionPolicy`: the effective permission as a value

Collapse the mode string and the `_bypass`/`_read_only`/`_auto` boolean trio into one small value type: a `PermissionMode` enum and a `PermissionPolicy` that answers the only questions a turn actually asks — *may this tool run without asking, must it ask first, or is it denied* — as methods, computed once and passed, not re-derived from flags in four methods. Two things become clean. The delegated clamp ("more-restrictive-of-caller-and-card") becomes a **meet** on the policy lattice instead of open-coded boolean logic, so "more restrictive" has exactly one definition. And manual/ask-by-default is a property of the policy (`unmatched → ask`), not an `if not auto and not read_only and not bypass` reconstructed at the bash gate. Every consult site — the bash gate, the tool preflight, the delegated-policy resolution — reads one object; changing the permission model is editing one type, not auditing six scattered string comparisons.

## `AgentConfiguration`: the sidecar as a schema

The per-agent `configuration.json` is persisted state, so it obeys the same rule: a pydantic `AgentConfiguration` owns its shape — model, permission mode (as the `PermissionMode` enum above, not a loose string), and `tools.bash.permissions` — with load / validate / merge / save on the model itself. The fragile `_persist_agent_allow_patterns` path — today: read the JSON, reach into `tools.bash.permissions`, merge without clobbering existing decisions, write it back — becomes a typed `configuration.grant_bash_patterns(...)` that cannot mis-key a field or silently drop a nested branch. Loading an agent validates its config at the boundary, so a malformed sidecar fails loudly at load rather than silently at the first `.get`.

## `TurnEvent` and the one event catalog

Replace `StreamEvent(Type, **data)` with a closed union — one frozen pydantic model per event: `TextChunk`, `ToolCallStarted`, `ToolResult`, `Suspended(interactions, plans)`, `Checkpoint`, `Relayed(child_event)`, `Done`, `Error`, and the rest — and, crucially, put it in the *same* catalog the repo already single-sources. `harness.core.events` is that catalog today; `TurnEvent` joins it, and so do the A2A `DataPart` payloads presently matched by raw `data["kind"]` (`artifact_event`, `compaction_request`, `autonomous_resume`, `input_response`, `artifact_image_annotations`). The result is one authoritative event vocabulary: the executor consumes `TurnEvent` with a typed match where an unhandled variant is a static error, not a silently-dropped `elif`; the wire carries validated members of the catalog rather than hand-built dicts read with `data.get(...)`; and the frontend union — already generated from the catalog's schema — covers them for free. `Checkpoint` stops being a control signal disguised as a data event: it is a variant, and the executor's reaction to it is explicit.

The in-process `TurnEvent` set may be a superset of what crosses the wire, but the rule holds in both directions: nothing on the wire is outside the catalog, and nothing in the catalog is read as a raw dict. This is the decision an earlier draft deferred ("code-generate one shared schema — defer, it couples the Python and TypeScript builds"): that coupling *already exists* in the repo, is deliberate, and is treated as a virtue — "two authoritative libraries and zero bespoke type-walking" — so the elegant move is to lean into the one catalog, not to grow a second untyped one beside it.

## `TurnMachine`: control flow you can see

Lift the turn lifecycle out of `stream()`/`execute()` into an explicit state machine. The states are the phases that are today implicit in the method's shape: `Planning` (one model call), `Deciding` (preflight the batch's permissions), `Executing` (drain the approved batch), `Suspended` (a human gate), `Compacting`, and the terminals `Done`/`Failed`/`Canceled`. Each state is a handler that takes the turn context and yields `TurnEvent`s plus the next state; the driver is a small loop that runs handlers until a terminal state. `return`/`continue`/`yield` woven through a mega-method become named transitions.

The terminals carry a typed **`TurnOutcome`**, not a free-form status string — so *why* a turn ended is data: `Completed`, `Failed(reason)`, `Canceled`, `Suspended(interactions)`. Reconciliation of orphaned turns, today an ad-hoc branch over (kind × state) with string reasons and a dead arm the audit already flagged as unreachable, becomes a total function over `(TurnRecord.kind, TurnOutcome)`: every combination is handled or is a type error, and the unreachable branch becomes unrepresentable rather than merely unused.

Two more things fall out of the machine that the durable-turn work reached for and missed. First, **suspension and resume are the same state, entered twice**: `Suspended` persists the `TurnRecord`'s pending interactions and stops; resume re-enters the machine at `Executing` with the answered decisions applied — identical whether the runtime was rebuilt from the checkpoint (top-level) or is still live (delegated). Second, the top-level/delegated divergence collapses into an injected **`Continuation`** strategy — `DurableSegment` (persist, close the A2A segment, rebuild later) or `InProcessPark` (await the answer in place) — chosen once at the `Suspended` transition, rather than forked through the body of two methods and a resolver. The state machine is what finally lets that unification be total instead of partial.

Because the machine's whole state is `(current_state, TurnRecord, conversation)`, each state is unit-testable in isolation, and a resumed turn is just the machine re-hydrated at `Suspended` — no special resume path to keep in sync with the main path.

## `TurnStore`: one facade, and an honestly-named `JobStore`

Stop claiming the task store is "everything." Define one `TurnStore` facade that owns a turn's durable state — the `TurnRecord`, the conversation checkpoint, and the A2A wire history — behind typed methods (`save`, `load`, `load_conversation`, `reconcile_orphans`), so there is exactly one object that reads and writes turn persistence and one place to reason about it. Rename `background_store` to `JobStore` and give it a one-sentence charter at the top of the file: *it owns background-job lifecycle and OS process-group reaping; it is not turn state.* The result is still two stores — but each name tells the truth, and nothing is a hidden third surface. "Single source of truth for a turn" becomes literally true because there is a single object that is it.

## The frontend that mirrors it

The same discipline, on the other side of the wire.

**One typed reader.** A generated discriminated union already exists (`events.ts` / `events.schema.json`), generated from the same pydantic catalog as `TurnEvent`; make it the *only* way parts are read. `reduceDataPart` and `reduceAgentLaneEvent` switch on the union's discriminant with an exhaustive `switch` and a `never` default, so a renamed or unknown kind is a compile error, not a `String(data.x ?? "")` that quietly yields `""`. `message.meta` gets a typed per-kind model; `ToolCall`'s ignored `permission`/`question`/`onPermission` props — vestigial dead weight — are removed, and the actionable prompt stays where it actually lives (the overlay).

**i18n every user-facing string.** Every label that today lives in a hand-written dictionary — `AGENT_STATE_LABEL_KEY`, the tool-status labels, the question-option scaffolding, `RISK_PALETTE`/`RISK_KEY` in the permission overlay — routes through next-intl. Nothing user-visible is hardcoded English inside a dict.

**The rule, stated for the frontend:** a dictionary that maps a fixed set of variants to behavior is a discriminated union in disguise (make it one); a dictionary of user-facing strings is missing i18n (route it through next-intl). A dict survives only as a genuinely open, transient map.

## The discipline that keeps entropy out

One invariant, enforced, is what prevents the slow return of the mess: **no untyped dict or bare enum at a boundary.** Persisted shapes are pydantic models; wire contracts are members of the one typed catalog; permission modes are the `PermissionMode` enum, not strings; telemetry attribute keys are a typed namespace, not scattered `"daisy.task.id"` string literals; rendered labels are i18n keys; the runtime↔executor and client↔server contracts are declared types, not conventions. A dict is permitted only as a local computation that never escapes its function. A lightweight CI guard — an AST check for `.get(` on `metadata`/event payloads and for bare permission-mode string literals, plus an ESLint rule against `Record<string, unknown>` at the reducer's read sites — makes the rule mechanical rather than aspirational.

## Build order

This is a refactor, so it must land in small, compiling, behavior-preserving steps — and the god-method split comes *after* the typed core exists to split into, never as a big-bang rewrite.

1. **`TurnRecord`.** Introduce it and route every `task.metadata` turn-state access through it; delete the raw-key pokes. Behavior-identical; the serialized bytes match the old keys until a later step is free to reshape them.
2. **`PermissionPolicy`.** Fold the mode string, the `_bypass`/`_read_only`/`_auto` trio, and the open-coded delegated clamp into the value type and its lattice meet. Behavior-identical; one object now answers every permission question.
3. **`AgentConfiguration`.** Wrap the sidecar in the schema, retype `permission_mode` to the enum, and move `_persist_agent_allow_patterns` onto the model as a typed grant. Validation now happens at load.
4. **`TurnEvent` + catalog unification.** Introduce the typed union in the shared `events` catalog behind the existing `StreamEvent` surface, fold the raw `DataPart.data["kind"]` payloads into it, migrate producers and consumers, and delete the `**data` bag and the `data.get(...)` reads.
5. **`TurnStore` + `JobStore`.** Wrap the current tables in the facade, migrate call sites, and rename/charter the background store.
6. **`TurnMachine`.** Extract states out of `stream()`/`execute()` one at a time — `Planning`, `Deciding`, `Executing`, `Suspended` — each already speaking `TurnEvent` and returning a `TurnOutcome` at the terminals, until the two methods are thin drivers and the `Continuation` strategy replaces the top-level/delegated fork. This is the largest step and the reason the first five exist: it is safe only once the record, the policy, the config, the events, and the store are typed.
7. **Frontend.** Adopt the generated union at the read sites with exhaustive switches; type `message.meta`; remove the vestigial `ToolCall` props; i18n every label dictionary.
8. **Guardrails.** Add the "no untyped dict or bare enum at a boundary" checks (Python AST guard covering metadata pokes, permission-mode literals, and telemetry keys; ESLint rule at the reducer read sites) to CI.

Each step is independently valuable and independently revertible; the codebase is more legible after step 1 and never less legible in between.

## Testing

Every step is behavior-preserving, so the bar is "the same observable behavior, with fewer ways to be wrong." The fake-LLM turn harness proven out in the durable-turn work is the regression net: it drives the real runtime and executor through suspend/resume and tool execution, and each refactor step must leave its transcripts unchanged. Additionally: `TurnRecord` round-trips to and from the exact task metadata the old keys produced (until a step deliberately reshapes it); `PermissionPolicy`'s lattice meet reproduces the current delegated-clamp decisions for every caller×card mode pair; the `TurnEvent` union reproduces the current `StreamEvent` sequence for the same scripted model; and each `TurnMachine` state is unit-tested in isolation now that it is a pure `(context) -> (events, next_state)` step, with the reconciliation covered as a total function over `(kind, TurnOutcome)`. On the frontend, the exhaustive switches make whole classes of "unknown kind silently dropped" bugs unrepresentable, which is its own test.

## Open questions

- The restrictiveness ordering of `PermissionMode` for the lattice meet. `bypass < auto < manual/default < read_only` is the intuitive chain, but `read_only` and `manual` are not strictly comparable — read-only forbids writes outright, while manual permits them after asking. Recommend modeling restrictiveness as two axes (side-effects-allowed × asking-required) and taking the componentwise meet, rather than forcing a single linear chain that would have to pick a wrong answer for that pair.
- Whether a `TurnMachine` state should be a coroutine/generator (keeps streaming ergonomics, but re-tangles control flow) or a pure `(context) -> (events, next_state)` step with a thin adapter that yields (maximally testable). Recommend the pure step.
- Whether `JobStore` should eventually move under `TurnStore`'s engine (one database, two logical stores) for operational simplicity, or stay a separate file/db; the charter matters more than the file boundary.
- Whether `AgentConfiguration` should also subsume the remote-agent trust/allow-list configuration, unifying all persisted agent config under one schema, or stay scoped to the per-agent sidecar; unify only if the two configs start sharing fields.

## Implementation status (as built)

This plan was implemented incrementally, each step verified against a fake-LLM harness that drives the real `HarnessAgentExecutor` + `DefaultRequestHandler` + `AppendOnlyTaskStore` through suspend/resume, delegated park, tool execution, and restart reconciliation (the harness is not committed, per the repo's no-committed-tests convention). Landed:

- **`PermissionMode`** — implemented in `core/tool_policy.py` (cohesive with the policy value types it sits beside; the plan named a separate `permissions.py`, but co-locating with `CallExecutionPolicy`/`ResolvedLocation` is less sprawl). The runtime's `(read_only, bypass, auto)` trio and the mode strings collapse to one typed mode with derived boolean views; `CallExecutionPolicy` carries one mode; the delegated clamp is `more_restrictive(...).clamped_for_delegation()`; the per-location `_call_policy` resolution reduces to a single-mode computation. `AgentConfiguration.permission_policy` exposes the card's mode typed.
- **`TurnRecord`** — `core/turn_record.py` (`TurnKind`, `PendingInteraction`, `ToolGate`, `AgentLane`). The executor and task store route all `task.metadata` turn-state through it. Serialization is byte-identical on the wire-visible keys (`referenceTaskIds`/`agentLane`, which the web client reads) and a tolerated superset on the backend-private `pendingInteraction` — so the reshape-under-one-namespaced-key remains a later step, exactly as the build order anticipated.
- **`AgentSidecar`** — `core/configuration.py` owns the `configuration.json` shape (lossless round-trip, `frontmatter_overrides`, typed `grant_bash_patterns`), replacing raw-dict poking in the merge / update / allow-grant paths.
- **`TurnEvent`** — `core/turn_events.py` is the closed typed union (one frozen dataclass per kind); all 83 producers yield variants; the executor consumes them with an exhaustive `isinstance` dispatch whose `else` raises. The legacy `StreamEvent(**data)` carrier and two dead variants were removed.
- **Store charters** — `AppendOnlyTaskStore` and `BackgroundJobStore` are documented as the single-turn-persistence surface and the separate job subsystem. The names were already honest (`BackgroundJobStore`, not a vague `background_store`), so no rename was done — a `TurnStore` facade over an already-single store would have been indirection without payoff.
- **Reconciliation** — orphan reconciliation is one total, tested pure function (`reconcile_action` over turn-kind × task-state) returning a typed `ReconcileAction`.
- **`TurnMachine`: `execute()` is now a per-turn state machine.** The 626-line `execute()` god-method is a six-line entry point that delegates to `_TurnRunner`, one single-use object per turn that makes the turn's state machine explicit. The ~two dozen locals that used to thread through deeply nested closures are instance attributes, and each phase is a named method, so `run()` reads as the turn's spine: `ingest → resolve_task (and any resume answer) → acknowledge_work_habits → acquire_serialization_lock → open_turn_span → [try] prepare_runtime → run_compaction_turn → compose_turn_input → stream_and_finalize [except fail] [finally teardown]`. A `_DONE` sentinel distinguishes a phase that finishes the turn before the lock is taken (a stale or partial answer — no teardown owed) from one that finishes inside the `try` (an autonomous no-op wake, a manual compaction — teardown runs once). The runtime-event dispatch is a dedicated `_TurnEventSink` — the consuming half of the one event catalog, one exhaustive typed `handle(event) -> bool` (True = a durable top-level suspension closed the segment) that also owns the assistant-text buffer and the turn telemetry span. A suspension forks to a `Continuation` strategy: a delegated turn parks in place (`_suspend_turn` returns False), a top-level turn closes its segment durably via `_suspend_durable_segment`. Behavior-preserving — identical await ordering and identical early-return/`finally` semantics; verified against the harness (happy-path completion, multi-tool batches, model errors, suspend/resume, delegated park, reconciliation).
- **CI guard** — `scripts/check_typed_boundaries.py` fails on any reintroduction of the `StreamEvent` carrier, a bare permission-mode string compare, or raw turn-metadata key indexing. It guards the boundaries that are fully typed today (not the DataPart/reducer catalog, which is not yet unified).
- **Frontend HITL cleanup** — the vestigial `permission`/`question`/`onPermission` prop chain (threaded through `chat-message` → `tool-group` → `ToolCall`, which ignored it) was removed end to end; the real HITL prompts remain in the overlays. Typechecks clean.
- **Frontend i18n of the tool-display labels** — `tool-display.ts`, previously ~40 hardcoded interpolated English strings (the "custom dictionaries missing i18n" the plan flagged), now routes through a `ToolDisplay` message namespace via an injected translator. The strings are complete sentences per case (a range or target is a real parameter, not an English-word-order fragment), landed in English and Japanese (78 keys each; the Japanese is natural but worth a native-speaker pass). Typechecks and lints clean; every referenced key exists in both locales.
- **One event catalog: the `DataPart` reducers now read it, exhaustively.** The pydantic `events` catalog (`WireEvent`) already existed and generates `events.ts`; the executor's `DataPart` payloads had drifted from it (`thinking.block_id`, `question.tool_call_id`, an unmodelled `warning`), and the reducers ignored the generated union in favour of `String(data.kind ?? "")`. The models were reconciled with what the executor emits; the schema generator now marks the `kind` discriminant required (pydantic defaults it, which left `kind?:` and blocked narrowing); `events.ts` was regenerated; and `reduceDataPart`/`reduceAgentLaneEvent` switch on the generated `WireEvent` discriminant with typed field access and a `never` default — so a renamed field, or a new kind a reducer forgets, is a compile error, not a silent `""`. Typechecks and lints clean.
- **`message.meta` is typed.** `ChatMessage.meta` moved from `Record<string, unknown>` to a `MessageMeta` interface (typed `permission`/`question`/`result`/`status`/`warning`/… ), so the ~77 read sites get real types rather than `unknown`; only the three resolve-handler writes needed adjusting (a `declined?` field on `ToolQuestion` and dropping two narrowing casts). Typechecks and lints clean.

Both god-methods named in the opening — the executor's `execute()` and the runtime's `stream()` — are now thin drivers, and the runtime's third giant, `_execute_tool()`, is decomposed alongside them. All eight build-order steps are landed.

- **`stream()`: 356 → 174 lines.** The turn loop is a thin driver over four extracted phases, each a cohesive async generator that yields wire events and hands back a loop directive through a small `_PhaseStep`/`_ModelCallOutcome` holder (the file's existing "generator writes into a passed mutable" pattern, as in `_drain_tools_concurrently`): `_build_turn_messages` (system prompt + conversation + first-iteration dynamic context), `_stream_model_call` (the abort-raced model stream and thinking indicators), `_finalize_no_tool_calls` (retry / agent-messaging / goal-continuation / done), and `_run_tool_batch` (preflight, suspend, drain, checkpoint). The cross-iteration goal counter became an instance attribute, matching the existing `_calls_this_turn`.
- **`_execute_tool()`: 979 → a ~15-line preamble + dispatch.** The permission/coercion/location/policy preamble runs once, then a declarative `_TOOL_HANDLERS` table routes the call to one of 22 per-tool handler methods (`_tool_bash`, `_tool_edit_or_write`, `_tool_spawn_or_remote`, …). Each handler carries its original branch body verbatim — the extraction was verified byte-for-byte against the pre-refactor branches — so a giant `if/elif` over `tool_name` became polymorphic dispatch with each tool independently readable.

Two scoping calls were made deliberately, not skipped:

- **No `TurnStore` facade / store rename.** `BackgroundJobStore` was already an honest name (not a vague `background_store`), and a `TurnStore` facade over the already-single `AppendOnlyTaskStore` would have been indirection without payoff. Both stores are chartered in place instead (build-order step 5's intent — a clear, single persistence surface — met without the wrapper).
- **`execute()` decomposed as one per-turn object, not four coroutine states.** The build order sketched separate `Planning`/`Deciding`/`Executing`/`Suspended` state handlers; the control flow is linear (a single stream loop, not a state graph), so a transition table would be ceremony that obscures. `_TurnRunner`'s named phases make the state explicit without a framework the flow doesn't need — the open question "coroutine-state vs pure step" is resolved in favour of neither, because there was no branching state machine to model.

The remaining frontend label maps that already route through i18n keys (`AGENT_STATE_LABEL_KEY`, the tool-status labels, `RISK_KEY`) are discriminated-union-shaped dictionaries of *keys*, not hardcoded strings, so they are not the i18n gap the plan targeted.
